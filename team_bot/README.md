# 배틀싸피 팀전 제출 코드

업로드된 **배틀싸피 사용자 매뉴얼 v1.1.10(build 20250917)**의 22·61~67쪽과 사용자가 제공한 팀전 규칙 이미지를 기준으로 작성했습니다. Python 3.9 이상과 표준 라이브러리만 사용합니다.

## 실행과 제출

1. `Player1_지역반_이름.py`, `Player2_지역반_이름.py`, `Player3_지역반_이름.py`를 각각 해당 팀원의 실제 파일명으로 바꿉니다. 예: `Player1_서울19_김싸피.py`.
2. 각 파일 상단의 `NICKNAME`을 본인의 `지역반_이름`으로 변경합니다. 12자 이내로 설정합니다. `PLAYER_SLOT`은 각 파일에 1·2·3으로 설정되어 있습니다.
3. 배틀싸피에서 팀전 대기 화면을 열고 세 파일을 각각 실행합니다. 세 파일은 각각 독립 실행할 수 있으며 같은 폴더의 다른 파일에 의존하지 않습니다.
4. 게임 화면에서 팀과 Player1·2·3 순서를 확인합니다.
5. 제출할 때는 코드 세 파일과 전략 메모를 하나의 ZIP으로 묶습니다. 닉네임과 실제 성명을 알 수 없어 현재 파일명은 교체용 이름입니다.

예:

```sh
python Player1_서울19_김싸피.py
```

기본 연결은 공개 기본 코드와 같은 `127.0.0.1:8747`, `INIT 닉네임`, 공백으로 끝나는 명령을 사용합니다. 공식 `libs/_bridge.py`가 같은 폴더에 있으면 그 통신 함수를 우선 사용합니다. 현재 배포 기본 코드가 이 통신 형식과 다르면 그 통신부에 `BattleBot.choose_action(parse_data(game_data))` 호출을 연결해야 합니다. 실제 게임 서버 접속은 이 환경에서 수행하지 않았습니다.

## 승리를 위한 판단 순서

- 지금 포탑을 파괴하거나 두 번째 적 탱크를 격파할 수 있으면 즉시 공격합니다. 같은 결과를 낼 수 있으면 메가탄을 아낍니다.
- 현재 위치에서 생존하면서 약해진 적을 격파할 수 있으면 그 탱크를 마무리합니다.
- 안전하게 보급할 수 있으면 메가탄 두 발까지 먼저 확보합니다. 일반탄 30과 메가탄 70의 조합으로 체력 100 탱크를 두 번의 사격에 제거할 수 있습니다. 보급을 위해 항상 열 발을 채우지는 않습니다.
- 이후 적 포탑까지의 접근 비용과 적 탱크 격파 비용을 비교하는 휴리스틱으로 목표를 정합니다. 현재 아군 포탑을 사격할 수 있는 적과 체력이 낮은 적의 우선순위를 높입니다.
- 세 코드는 공통으로 보이는 체력 정보를 이용해 약해진 적에 집중합니다. 아군 칸은 장애물로 취급하며, 경로 비용이 비슷하면 Player2·3이 서로 다른 방향을 선호하도록 하여 길막을 줄입니다. 별도의 팀 간 통신이나 완전한 공동 계획은 구현하지 않았습니다.
- 매 턴 맵을 다시 읽어 A* 탐색을 수행합니다. 상태에는 위치, 체력, 두 종류의 탄약, 파괴한 나무, 적 잔여 체력이 포함됩니다. 같은 칸이라도 남은 자원이 다른 상태를 구분합니다.

## 옐로카드와 생존 처리

- 아군 포탑을 중심으로 하는 3×3 영역에는 이동하지 않습니다. 모래 진입의 체력 10 소모도 누적 계산합니다.
- 이동은 현재 비어 있는 일반 지형·모래에만 합니다. 아군, 물, 바위, 나무, 보급 시설에는 진입하지 않습니다.
- 사거리 3칸 안의 첫 장애물을 확인합니다. 나무 또는 적이 첫 피격 대상인 경우에만 발사하여 허공·바위·시설·아군 방향의 불필요한 사격을 방지합니다.
- 남은 일반탄·메가탄을 확인하고, 메가탄 10발 상태에서는 보급하지 않습니다. 두 탄종은 자동으로 대체하지 않습니다.
- 일반적인 판단에서는 제자리 대기·회전 명령을 사용하지 않습니다. 이동·유효 사격·해독 중 아무것도 가능한 행동이 없는 봉쇄 상태에서는 `S`가 최후의 선택입니다. **이 경우까지 옐로카드 0장을 보장할 수는 없습니다.**
- 적의 메가탄 보유량과 방향은 입력되지 않으므로 기본적으로 적 한 대가 한 라운드에 70의 피해를 줄 수 있다고 가정합니다. 예측상 위험한 정지 사격보다 생존할 수 있는 이동을 선호합니다. 이 보수적인 설정은 필요하면 `enemy_damage`로 바꿀 수 있습니다.
- 탐색은 기본적으로 140ms와 3,500개 상태 제한을 사용하며 초과하면 합법 행동 중 생존·피해·엄폐·전진 순으로 고릅니다. 이는 실시간 운영체제 수준의 엄격한 시간 보장은 아닙니다.
- 알고리즘 예외가 생기면 간단한 합법 행동 선택으로 복구합니다. 제공된 상태 자체가 잘못됐거나 실제 통신 규약이 다르면 별도의 수정이 필요합니다.

## 암호 해독과 규칙 변경

매뉴얼 66쪽 예시의 `SRKKCVJJRWP → BATTLESSAFY`에 맞춰 암호화 시프트 17, 즉 해독할 때 각 알파벳에 +9를 적용합니다. 실제 경기에서 다른 치환 간격을 사용하면 `caesar_shift`를 수정해야 합니다. 짧은 암호문의 영어 빈도만으로 키를 확정하지 않습니다.

파일의 `Rules` 값을 직접 바꾸거나 JSON 파일로 덮어쓸 수 있습니다. 예:

```json
{
  "caesar_shift": 17,
  "enemy_damage": 70,
  "time_budget_ms": 140,
  "max_nodes": 3500
}
```

```sh
python Player1_지역반_이름.py --rules rules.json
```

보급을 사용하지 않으려면 `"caesar_shift": null`로 설정합니다. 팀전 기본값은 상대 탱크 3대입니다. 1대1·2대2 경기에는 `expected_enemy_tanks`를 해당 대수로 바꾸며, 과목 평가 모드에는 `team_mode: false`가 필요합니다.

## 검증과 한계

- 직접 작성한 25개 테스트 통과: 아군 포탑 주변 이동 금지, 아군·바위 뒤 사격 금지, 즉시 승리, 두 번째 탱크 격파, 포탄 절약, 탄약 0, 보급 상한, 누적 모래 피해, 입력 파싱, TCP 분할 수신, 종료 표식, 예외 복구, 무작위 팀전 상태의 합법 행동 등을 확인했습니다.
- 별도의 공개 비공식 연습 시뮬레이터에서 기본·좌우 반전 12개 맵을 모두 완료했고 무효 명령은 0회였습니다. 이때는 연습 시뮬레이터 규칙에 맞춰 `team_mode=false`, `enemy_damage=30`을 사용했습니다.
- 추가로 16×16 무작위 맵 30개에서 반환 명령의 합법성을 확인했습니다. 이 실행 환경의 평균 판단 시간은 141.049ms, 최대는 144.01ms였습니다. 다른 PC의 시간이나 경기 승률을 보장하는 수치는 아닙니다.
- 이 테스트는 실제 공식 엔진의 3대3 대전이 아닙니다. 실제 승률, 100턴 판정 결과, 다른 참가자의 전략에 대한 우위를 검증한 수치는 없습니다.
- 장기 탐색에서는 적이 현재 위치에 머무르며 사격한다고 모델링하고, 적의 다음 이동으로 생길 사선은 추가 위험 비용으로 처리합니다. 모든 상대 행동을 읽는 완전한 미니맥스나 학습된 상대 예측 모델은 아닙니다.
- 승리를 보장하는 무적 코드는 아닙니다. 실제 대전에서 받은 입력과 행동 로그를 수집하면 표적 우선순위, 위험 비용과 보급 시점을 추가 조정할 수 있습니다.
