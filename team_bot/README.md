# 배틀싸피 팀전 v2 — 공격 1대 · 수비 2대

[실행기 포함 전체 ZIP 다운로드](battle_ssafy_v2.zip?raw=true) · [제출 코드만 ZIP](submission.zip?raw=true)

사용자가 제공한 사용자 매뉴얼 v1.1.10(build 20250917)과 팀전 규칙을 적용했습니다. 기존 v1의 2전 2승은 사용자의 관측이며, **v2의 실전 승률은 아직 측정하지 않았습니다.**

## 실행

1. ZIP을 새 폴더에 전부 풀고 각 `Player1/2/3_지역반_이름.py`의 `NICKNAME`과 파일명을 실제 팀원 정보로 바꿉니다. Player 번호는 유지합니다.
2. 배틀싸피 팀전 대기 화면을 엽니다.
3. Windows에서는 `Run_Player1.bat`, `Run_Player2.bat`, `Run_Player3.bat`를 각각 실행합니다. 각 배치 파일은 같은 번호의 `Player번호_*.py`를 찾아 실행하므로 이름 변경 후에도 사용할 수 있습니다. 번호별 파일은 한 개씩만 두세요.
4. 게임 화면에서도 실제 Player1·2·3 순서를 코드 번호와 맞춥니다. 파일명만 바꿔서는 역할이 바뀌지 않으며 코드의 `PLAYER_SLOT` 값으로 결정됩니다.
5. 제출 시에는 코드 세 개와 전략 메모만 최종 제출 ZIP으로 묶습니다. 제공 ZIP의 배치 파일과 IDE 설정은 로컬 실행 보조용입니다.

개별 파일은 표준 라이브러리만 사용하는 독립 실행 코드입니다. 별도 Python 모듈 설치가 필요하지 않습니다.

```sh
python Player1_지역반_이름.py
```

기본 통신은 `127.0.0.1:8747`, `INIT 닉네임`, 공백으로 끝나는 명령입니다. 공식 `libs/_bridge.py`가 있으면 그 통신 함수를 우선 사용합니다. 현재 게임 배포본의 통신 규약이 다르면 그 통신부를 유지하여 연결해야 합니다.

## 역할

| 코드 | 기본 역할 | 행동 |
|---|---|---|
| Player1 | 공격수 | 적 포탑 공격을 우선하며 사선과 예상 피해를 피합니다. 멀리 있는 적 탱크를 추격하지 않습니다. 안전한 포탑 사격이 비승리 탱크 마무리보다 우선입니다. |
| Player2 | 수비수 | 아군 포탑 한쪽 측면을 순찰하고 접근하는 적을 요격합니다. |
| Player3 | 수비수 | 반대쪽 측면을 우선 순찰하며 접근하는 적을 함께 제거합니다. |

두 수비수는 기본적으로 포탑의 체비쇼프 거리 2~4칸에서 자리를 찾고, 6칸을 넘는 추격을 제한합니다. 처음부터 방어 범위 밖에서 시작했다면 포탑 쪽으로 돌아오는 경로를 찾습니다. 지형과 아군 점유 때문에 측면을 완전히 나누지 못할 수 있습니다.

팀전에서는 제자리 대기가 페널티 대상이므로 수비도 안전한 칸 사이를 순찰합니다. 아군 포탑 주변 진입 금지 3×3 영역은 그대로 피합니다. 현재 포탑 사격이 가능한 적을 가장 긴급한 위협으로 보고, 포탑까지 맨해튼 거리 8칸 이내의 적도 요격 대상으로 취급합니다. 수비수가 먼 적이나 적 포탑을 향해 전진하는 일반 목표 선택은 제거했습니다.

어떤 역할이든 당장 적 포탑 파괴나 두 번째 적 탱크 격파로 승리할 수 있으면 그 사격이 우선입니다. 수비수는 아군 포탑이 다음 적 일제 사격에 파괴될 수 있으면, 위협 제거 또는 안전하게 사선을 몸으로 막는 행동을 먼저 검토합니다. 이동 후 포탑의 치명적인 사선을 새로 열어 주는 행동에는 큰 비용을 부여합니다.

## 허공 사격 보완

모든 행동은 전송 직전에 **탐색에서 가정한 맵이 아닌 현재 수신 원본 맵**으로 다시 검사합니다.

- 직선 3칸 이내의 첫 장애물만 확인합니다.
- 그 대상이 현재 체력이 남은 적 또는 실제 나무일 때만 사격합니다.
- 아군·바위·시설·알 수 없는 기호에 막히거나 사거리 내 표적이 없으면 해당 사격을 교체합니다.
- 일반탄·메가탄 수량도 마지막에 재검사합니다.
- 적을 쏜 뒤 다음 수신 상태에서 적 체력 감소가 전혀 관측되지 않으면, 같은 위치·방향·표적 좌표의 사격을 3번의 판단 동안 차단하고 다른 위치를 찾습니다. 실제 HP 감소 원인을 완전히 식별하는 것은 아니며, 로그에는 '피해 감소 미관측'으로 표시합니다.

사용자가 본 사격 장면의 로그가 없어 직접 원인은 확정하지 않았습니다. 최신 맵에서도 실제 게임이 사격을 거절하거나 입력 정보가 지연되는 상황까지 명중을 보장하지는 않습니다. 다음 로그가 원인 확인에 도움이 됩니다.

```text
[RUNTIME] CPython 3.12.x / slot=1 / v2.0
[ACTION v2.0 slot=1] R F (...) target=X@(r, c) distance=3
[VERIFY] Previous shot caused no observed HP drop; same firing position temporarily blocked
```

나무를 파괴하는 유효 사격은 계속 허용합니다. 수비 순찰의 일반 이동이 가능하면 관련 없는 나무 사격보다 이동을 우선하도록 했습니다.

## 모래 회피 보완

기존에는 모래 진입의 피해 비용이 작았고, 제한 시간에 걸려 부분 경로를 고를 때 남은 거리부터 비교하는 문제가 있었습니다.

v2는 먼저 **모래를 통과할 수 없는 것으로 놓고** 일반 지형 경로를 찾습니다. 모래 지름길보다 일반 지형 우회로가 길어도 우회로를 먼저 사용합니다. 부분 경로도 누적 행동 비용과 남은 비용을 합쳐 비교하도록 수정했습니다.

공격수는 일반 지형으로 목표 사격 위치까지 갈 경로가 없는 경우에만 모래 경로를 다시 찾습니다. 수비수도 즉시 포탑 파괴를 막을 수 있는 유일한 길이 모래일 때에는 포탑 보호를 우선합니다. 이 경우에도 모래 진입의 체력 10 소모를 누적 계산하고 추가 비용 50을 적용합니다. 현재 위치가 완전히 막혀 있고 합법 행동이 모래 이동뿐인 경우에도 탈출을 위해 허용할 수 있습니다. 수비수는 가능한 일반 지형 순찰을 우선합니다. 따라서 **모래를 영구 금지하는 설정은 아니며**, 필요한 통행과 탈출은 남겨 두었습니다.

## CPython / PyCharm 설정

권장 런타임은 **일반 CPython 3.12**, 코드 호환 범위는 CPython 3.9 이상입니다. 저장소의 기존 PyCharm 설정은 `Python 3.9`였으며, PyPy를 지정한 설정은 발견되지 않았습니다. 이번 브랜치의 프로젝트 SDK 이름과 `.python-version`은 Python 3.12 기준으로 정리했습니다.

Windows 배치 실행기는 아래 순서로 런타임을 검사하고 **`platform.python_implementation() == 'CPython'`일 때만** 실행합니다.

1. `BATTLE_PYTHON` 환경 변수로 지정한 `python.exe`가 있으면 그 경로만 검사
2. 프로젝트 `.venv\Scripts\python.exe`
3. `py -3.12`
4. `py -3`
5. `python`

CPython을 찾지 못하면 안내를 출력하며 PyPy로 실행하지 않습니다. Python을 자동 설치하거나 사용자 PC의 전역 인터프리터를 변경하지 않습니다. Windows 배치 파일은 이 Linux 검증 환경에서 실행하지 못했으며, 실제 Windows에서의 선택 확인이 필요합니다.

PyCharm의 실행 버튼을 사용할 경우 PC에서 다음을 한 번 설정해야 합니다.

`Settings → Project → Python Interpreter → Add Interpreter → Local Interpreter → CPython의 python.exe 선택`

예를 들어 설치한 `Python312\python.exe` 또는 그 CPython으로 만든 가상 환경을 선택합니다. SDK 이름만 바꿔서는 사용자 PC의 실행 파일이 교체되지 않습니다. 실행 로그 첫 줄이 `CPython`으로 표시되는지 확인하세요.

## 조정과 검증

파일의 `Rules` 또는 `--rules rules.json`으로 변경할 수 있습니다.

```json
{
  "role": "auto",
  "defense_leash": 6,
  "threat_radius": 8,
  "sand_cost": 50,
  "caesar_shift": 17,
  "time_budget_ms": 140,
  "max_nodes": 3500
}
```

`role: auto`는 Player1 공격, Player2·3 수비입니다. 메가탄 보급은 매뉴얼 66쪽 예시의 치환 간격 17(해독 시 +9)을 기본값으로 사용합니다. 실제 경기 키가 다르면 변경하세요. 적 탄약 정보는 없으므로 사선상의 적 한 대당 최대 70 피해를 가정합니다. 장기 탐색에서는 적을 현재 위치에 두고, 이동으로 새로 생길 수 있는 사선은 추가 위험 비용으로 반영합니다.

자체 검증: 기존 25개와 새 회귀 검사 23개, 총 48개 테스트 통과. 새 검사에는 원본 맵의 허공/차폐 사격 차단, 가상 표적 사격 교체, 미명중 의심 사격 반복 차단, 긴 일반 지형 우회로 우선, 불가피한 모래 통과, 치명적 모래 회피, 공격수 포탑 우선, 수비수 위협 요격·측면 분리·30턴 순찰 범위, 역할별 무작위 지도 검사가 포함됩니다. 실제 공식 3대3 엔진을 이 환경에서 실행한 것은 아닙니다.

개발용 전체 검사와 테스트 파일은 `tests/`에 있습니다. `python tests/run_tests.py`로 실행합니다. 테스트 파일은 실제 제출 ZIP에는 필요하지 않습니다.
